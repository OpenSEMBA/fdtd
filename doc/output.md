# Probe Output

This page describes the files generated by each probe type.
In the filename patterns below, `R` is the root of the input filename, `N` is
the probe name, `F` is the sampled field or component, `C` is the coordinate,
and `B` is the probe bounding box.

Time-domain probes buffer samples in memory and are flushed to disk every 128
steps (`OUTPUT_TIME_BUFFER_SIZE`). Point, wire and bulk probes are flushed every 4096 steps
(`SMALL_PROBE_BUFFER_SIZE`) because they are small; volumetric probes (movies)
and line probes keep the 128-step cadence. `-flushdata <minutes>` adds a time-based flush that
flushes every probe type. The estimated buffer memory per probe type is printed at `Init Timing`
(see [init_timing.md](init_timing.md)).

## Scalar Text Output

Point, wire, bulk-current, line, and far-field probes publish formatted `.dat`
files beside the originating `.fdtd.json` input.
They do not use probe-specific directories and do not create binary artifacts
or metadata sidecars.

| Probe type | Without MPI | With MPI |
| --- | --- | --- |
| `point`, time domain | `R_N_F_C_tm.dat` | The same single `.dat` file. |
| `point`, frequency domain | `R_N_F_C_fq.dat` | The same single `.dat` file. |
| `wire`, FDTD current | `R_N_W{axis}_C_s{node}_tm.dat` | The same single `.dat` file. |
| `wire`, MTLN voltage or current | `R_N_<probe>_<bundle>.dat` | The same single `.dat` file, written by the selected owning rank. |
| `bulkCurrent` | `R_N_J{axis}_B_tm.dat` | The same single `.dat` file, reduced and written by rank 0. |
| `line` | `R_N_LI_tm.dat` | The same single `.dat` file, reduced and written by rank 0. |
| `farField` | `R_N_FF_B.dat` | The same single `.dat` file. |

Point probes configured for both domains produce one `_tm.dat` file and one
`_fq.dat` file.
Far-field probes are always frequency-domain results, despite not using the
`_fq` suffix.

For MTLN voltage probes, each column corresponds to a bundle conductor referred
to its surrounding shield. In full-wave problems the conductor acting as the
shield of a `shieldedMultiwire` contained within another cable is omitted,
since it has no reference of its own. In standalone MTLN problems
(`mtlnProblem`), every conductor is reported, with the outermost ones referred
to the reference/ground conductor.

## Volumetric Output

`movie` probes write their files in a directory whose basename is
`P = R_N_F_B`.
The visible files are identical for builds with and without MPI; MPI transfers
or collectively writes the rank-local data into the canonical files.

| Probe type | Without MPI | With MPI |
| --- | --- | --- |
| `movie`, time domain | `P/P.xdmf`, `P/P.h5`, `P/P_geometry.xdmf`, and `P/P_geometry.h5` | The same four files. |
| frequency slice (`movie`, frequency domain) | `P/P.xdmf`, `P/P.h5`, `P/P_geometry.xdmf`, and `P/P_geometry.h5` | The same four files. |

Movies and frequency slices do not create a `.bin` file.
They create field data in `P.xdmf` and `P.h5`, plus the geometry companion in
`P_geometry.xdmf` and `P_geometry.h5`.
The `.xdmf` files describe the corresponding data and geometry stored in HDF5.

The HDF5 writer cannot append to an existing file. When a run is resumed
(`-r`), the `P.xdmf` and `P.h5` of the previous run are moved to
`P/before_resume_K/` (`K` is the first unused number) and the resumed run
writes new files, so the frames written before the resume are kept but are not
joined to the new ones. Scalar `.dat` probes are appended instead.

The frequency sums of point probes are saved with each restart checkpoint in
`<probe>_fq.dat.dft`, and those of frequency slices in `<slice folder>/..._at_x_y_z.dft`
(one per MPI participant), and restored on resume, so a resumed output matches an
uninterrupted run. A resumed run must be given the same step count with `-n`,
the solver step count, as the run it resumes.

## Resuming a Run

Restart checkpoints are written every `restartFlushMinutes` (JSON) or `-flush <minutes>`
(console), whichever is set with the higher priority. The init timing report then shows
`Restart FIELDS flush: every N minutes`. Without either, fields are only saved at the end
of the run or with `-cpumax`.

To continue after a crash or a kill:

1. Relaunch the same case with `-r` and the same step count `-n` as the original run.
2. Use the same number of MPI processes as the original run. A resume with a different
   count aborts before any field is read.
3. The run continues from the last checkpoint. There is one file per rank,
   `<case>_<k>.fields` with `k` from 1 to the number of ranks.

```sh
mpirun -np 4 semba-fdtd -i case.fdtd.json -r -n 20000
```

A checkpoint written by an older version has no process-count header and cannot be
resumed. Run it again from the start with `-s`.

Checkpoints are only written at a flush, so the steps after the last one are recomputed.
Each rank writes its file locally and all ranks decide together when to flush.

## Geometry Map Output

The `-mapvtk` option creates a geometry map rather than a JSON
probe.
All `.vtu` pieces are collected in a single directory whose basename is
`R__MAP`.
Without MPI, that directory contains one `.vtu` piece.
With MPI, it contains one `.vtu` piece for every participating rank, and a
root-level `.pvtu` descriptor beside the input references all pieces.
Geometry maps do not publish text sidecars.

Probe outputs do not create JSON descriptors or a run output manifest.
Binary values retain their established byte order, numeric representation,
record size, component order, and complex-value convention.
