# C++ MPI Migration Plan

This plan tracks Fortran MPI behavior that is still missing, partial, or only
present in inactive translated C++ scaffolding.  Keep work packages independent:
one agent should own one row at a time and add strict serial-vs-MPI and
Fortran-vs-C++ tests with the implementation.

## Status Key

- `done-active`: implemented in the executable path and covered by tests.
- `partial-active`: some executable behavior exists, but Fortran parity is not
  complete.
- `scaffold`: translated C++ exists but is not linked into the active solver or
  is still placeholder quality.
- `todo`: no usable C++ implementation yet.

## Required Tests

1. C++ unit tests for MPI decomposition and communicator construction.
2. C++ two-rank unit tests for MTLN bundle voltage and external-field exchange.
3. Python full-system strict tests comparing serial C++ vs MPI C++ probe bytes for
   `-mpidir x`, `-mpidir y`, and `-mpidir z`.
4. Python full-system byte tests comparing Fortran MPI vs C++ MPI for cases that
   are already exact in serial mode.
5. Performance benchmarks for ranks `1`, `2`, and `4` against the Fortran MPI
   executable, using Release builds.

## Current Priority

The next highest-value implementation target is true slice-local FDTD sweeps.
C++ now has active MTLN bundle MPI and tangential field ghost exchange, but each
rank still performs most full-domain field work. That keeps many byte-parity
tests passing while leaving MPI scaling behind Fortran.
